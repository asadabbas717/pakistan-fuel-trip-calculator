# Dependency security backports

Reviewed 15 October 2026; review expires 15 November 2026. These are source fixes, not claims that upstream has published patched versions. No audit entries or package versions are falsified.

The SDK 57 toolchain includes three packages whose latest registry releases still have unresolved advisories. `npm audit fix --force` suggests incompatible framework changes. To preserve SDK 57, root `postinstall` applies narrowly scoped, checksum-pinned backports from `dependency-patches.json`. Every installed copy recorded by the lockfile must match its expected package version and complete source checksum. An unexpected upstream change or missing patch fails installation/verification. No extra dependency or paid service is required.

| Advisory                                                                                   | Remediation                                                                                                                                                                                                                                                                                                                        |
| ------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm), braces 3.0.3     | Bound parser nesting to 128 levels and iteratively validate AST depth before compile/expand/stringify. Also reject cyclic ASTs and excessive AST node counts. Ordinary brace expansion remains supported.                                                                                                                          |
| [GHSA-86w9-cpqp-85rv](https://github.com/advisories/GHSA-86w9-cpqp-85rv), node-forge 1.4.0 | Require the nested DigestAlgorithm count to exactly match the OID plus the optional NULL captured by validation. Based on the approach in [upstream PR 1152](https://github.com/digitalbazaar/forge/pull/1152), with exact checks that also reject an unexpected second element when NULL is absent and non-empty NULL parameters. |
| [GHSA-hp3w-g68c-fv3c](https://github.com/advisories/GHSA-hp3w-g68c-fv3c), sprintf-js 1.0.3 | Reject width or precision above 10,000 before formatting/caching; ordinary numeric and string formatting remains supported.                                                                                                                                                                                                        |
| [GHSA-w5hq-g745-h8pq](https://github.com/advisories/GHSA-w5hq-g745-h8pq), uuid             | Scope the override to `xcode` and use CommonJS-compatible uuid 11.1.1, which contains the bounds fix. Test actual Xcode project ID generation and undersized-buffer rejection.                                                                                                                                                     |

Run `npm ci`, `npm run test:security` and `npm run audit:security`. Do not install with `--ignore-scripts`; verification deliberately fails if the backports are absent. Tests exercise deeply nested patterns/ASTs, real RSA verification with malformed nested structures, formatting limits and Xcode UUID compatibility. These packages are build tooling; verify bundle source maps when assessing app-runtime reachability.

The security gate runs the live registry audit and retains its unchanged JSON in `.expo/security-audit.json` (also a CI artifact). Raw npm audit will continue to flag the three original registry versions because it does not inspect source backports. The gate verifies installed source checksums and runs exploit regressions before recognizing only these exact remediated advisory IDs. Any new root advisory, missing/modified patch, audit error or expired review fails the gate, including moderate findings. Dependency-chain entries are traced to their root advisories rather than counted as separate vulnerabilities.

When upstream publishes fixes, replace the backports with compatible releases, remove only the corresponding manifest entries and run the complete quality/build checks. Do not extend the review date without checking upstream and rerunning regression tests. Keep older audit snapshots in `docs/` as historical evidence; the live report and this remediation record describe current status.
